**Live addresses:**

| What | Address |
|---|---|
| Main site (landing, signup, login) | https://rahisishabiashara.com |
| A shop's own address | `https://<shop-word>.rahisishabiashara.com` |

**Docker is not used in production.** Render and Vercel run the code themselves, so no server was installed by hand. The Docker file in `infra/docker-compose.yml` is for the laptop only, and nothing uses the Redis container in it.

## 3. How it fits together

```
 Visitor's browser
       |   https://rahisishabiashara.com   and   https://<shop>.rahisishabiashara.com
       v
 +----------------+
 |  VERCEL        |   the website. Its gate guard (proxy.js) asks the API
 |  Next.js       |   "which shop is this address?"
 +----------------+
       |   browser calls the API, with the login cookie
       v
 +----------------+
 |  RENDER        |   api.rahisishabiashara.com
 |  Express API   |
 +----------------+
       |   DATABASE_URL, logging in as rahisisha_user (never the boss user)
       v
 +----------------+
 |  NEON          |   Postgres, with row-level security: each shop sees only its own rows
 +----------------+

 DNS: the domain is bought at Host Pinnacle. Its nameservers point to Vercel.
      Vercel DNS holds the apex (@), the wildcard (*) and api (pointing to Render).
```

## 4. Settings each piece needs (names only, never values)

**Render, service `rahisisha-api-staging`:** build command `npm ci`, start command `npm start`.

| Name | Meaning |
|---|---|
| `NODE_VERSION` | `22` |
| `NODE_ENV` | `production` (secure cookies, https only) |
| `JWT_SECRET` | generated by Render. Different from the laptop's. |
| `DATABASE_URL` | the Neon address for `rahisisha_user`, with `?sslmode=require` |
| `WEB_ORIGIN` | `https://rahisishabiashara.com` |
| `ROOT_DOMAIN` | `rahisishabiashara.com` |
| `COOKIE_DOMAIN` | `.rahisishabiashara.com` (leading dot) |

**Vercel, project `rahisisha-web`:** `NEXT_PUBLIC_API_URL` (must end in `/v1`) and `ROOT_DOMAIN`.

Every other setting, and which ones are secret: `docs/secrets.md`. Real values live only in Render, Vercel and a password manager.

## 5. Known limits of this setup (honest)

- **The free Render API sleeps** after 15 minutes of no visits, so the first visit after a quiet spell can take about a minute.
- **Vercel Hobby is for personal, non-commercial use.** Upgrade before charging customers.
- **Neon free** sleeps when idle and has small storage.
- **Demo accounts have a public password** (`scripts/demo-data.sql`). They must never hold real data.
- **The words `api` and `www` are not reserved** yet. A shop with that name could not log in at its own address (`capstone/STAGING.md`, known gaps).
- **Free plans change.** Check each company's pricing page.

## PIECE BY PIECE (simple words)

**Neon, Render and Vercel** are like three rented stalls in a market: one keeps the stock book (the database), one is the shopkeeper who answers questions (the API), and one is the shop window customers look at (the website). You don't own the market. The market looks after the building.

**DNS** is the name board at the market gate. It tells a visitor "rahisishabiashara.com is stall number so-and-so". The wildcard (`*`) means every shop name under your domain, like `mamanjeri.rahisishabiashara.com`, goes to the same stall.

**Settings with names only** is like writing "the safe's key is in the drawer", but never taping the key itself to the wall of a public market.

**Section 6, "NOT CHECKED YET"** is the honest price board: it says what is still not proven, so nobody trusts it more than it deserves.
